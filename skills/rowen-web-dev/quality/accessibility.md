# Accessibility as Task Completion

Target accessible task completion, not a vanity score.

Load feature-specific checks only when relevant.

Always consider:
- semantic structure;
- keyboard operation;
- visible focus;
- meaningful labels/names;
- text contrast/readability;
- zoom/large text/responsive reflow;
- status/error communication;
- motion preferences.

Forms additionally require visible/associated labels, clear errors, retained values, appropriate autocomplete/input semantics and compatibility with keyboard, touch, autofill and password managers.

Dialogs/overlays require appropriate focus movement/restoration and keyboard behavior.

Charts/data visualization, themes, SVGs and other specialized features require their own relevant checks rather than generic "accessibility passed" claims.
